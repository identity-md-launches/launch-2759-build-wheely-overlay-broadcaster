# WHEELY Overlay design system

## Overview

WHEELY serves a broadcast operator preparing Squeekchain browser sources. The control room is a quiet, warm studio workbench: cream surfaces, dark green-black text and a tangerine primary action. The broadcast widgets use compact opaque information surfaces inside an otherwise fully transparent canvas. Keeping those two formats distinct preserves on-camera legibility without turning the stream into a full-page dashboard.

The main task is selecting, configuring and copying a source URL. The desktop work area pairs the live composition preview with a settings column. A real-time lineup and a session telemetry log follow it. At phone widths the preview and its copy action come first; settings and the lineup follow in the same document order.

Source of truth: `src/styles/control.css`, `src/styles/overlay.css`, `src/scripts/control.js`, and `src/scripts/widgets.js`. `dist/` is an exact static copy of `src/`, generated by `scripts/build.mjs`.

## Typography

`--font-ui` is `Arial, Helvetica, sans-serif`; no web font loads. `--font-data` is `'SFMono-Regular', Consolas, 'Liberation Mono', monospace`, used for URLs, endpoint addresses and resolution metadata. Prose stays sans-serif. The implementation requests only weights **400** and **700**, using installed platform faces.

The control room has six declared size tokens in `control.css`:

| Token | Size | Role |
| --- | --- | --- |
| `--text-xs` | 12 px | Captions, compact labels and source metadata |
| `--text-sm` | 14 px | Body copy, buttons and navigation |
| `--text-base` | 16 px | Card titles, larger fields and mobile input text |
| `--text-lg` | 20 px | Section headings and telemetry totals |
| `--text-xl` | 28 px | Brand and mobile page title |
| `--text-display` | 36 px | Desktop page title |

The video format has its own six-step optical scale: `--overlay-caption` 18 px, `--overlay-label` 20 px, `--overlay-body` 24 px, `--overlay-value` 36 px, `--overlay-metric` 44 px and `--overlay-timer` 80 px. These are source-canvas sizes before automatic fitting and the operator's scale. They are not phone UI font sizes.

Body line height is 1.5 in the control room and 1.45 in widgets. Headings use 1.15–1.4; wrapped integrity evidence uses 1.5. Titles use restrained negative tracking (`-.035em` for the page title/timer, `-.02em` for section headings). Body text is naturally spaced. Heading text balances; short prose uses pretty wrapping. Telemetry and timers use tabular numbers. IDs and evidence can wrap; essential values never use line clamping or ellipsis. Native URL fields keep the full selectable value and horizontal editing behavior.

## Layout

Grouping uses roughly 8–12 px within a group, 20–28 px between neighboring components, and 32–42 px between major sections. Shared edges are established by the main content inset and column grid. The control room has a 1640 px maximum main width and a 210 px fixed rail at the largest normal desktop layout; its main inset is 36 px. The preview/settings grid uses a flexible main column, a 280 px settings column and a 26 px gap.

Breakpoints are implemented in `control.css`:

| Width | Behavior |
| --- | --- |
| At least 1700 px | Main inset grows to 48 px; settings become 300 px; five lineup cards share a row. |
| Up to 1250 px | Rail narrows to 180 px, main inset to 26 px, settings to 250 px; the source URL/button can wrap. |
| Up to 1000 px | Rail narrows to 150 px; settings move below the preview and use a two-column form; lineup uses two columns. |
| Up to 680 px | Rail becomes a horizontal brand/setup header; main inset is 20 px; copy action fills its row; lineup becomes one column. Mobile text inputs use 16 px. |
| Up to 370 px | Main inset becomes 16 px and compact labels adapt, preserving the main action. |

The composition preview is a 16:9 frame. A genuine 1920 × 1080 widget iframe is scaled to its width, leaving the widget's own canvas sizing intact. The original `wheel-scene.svg` is a clearly illustrated composition backdrop. The five card previews are separate live iframes over a checkerboard transparency indicator; their smaller source viewports make previews more legible.

Every standalone source sets **both html and body backgrounds to transparent**, margin/padding to zero, and overflow to hidden. `color-scheme: normal` avoids the browser's automatic opaque dark iframe canvas. Widget surfaces are the only painted UI. At 1920 × 1080, safe-area insets are 48 px. Fluid clamping keeps margins at least 12 px. Ticker and commands anchor at the bottom; timer, alerts and integrity anchor at the top. `side` changes the physical anchor and transform origin. `fitScale()` in `widgets.js` takes the smaller of requested scale, available-width scale and available-height scale, preventing source cropping.

Browser checks observed no page-level horizontal overflow at 320, 360, 390, 1280, 1440 and 1920 px. The 390 × 844 live capture puts the main copy button at y=645.45 with a 45 px height, inside the first screen. Both themes and all five routes were checked at 1280 × 720 and 1920 × 1080. Native 200% zoom and physical-device viewing remain unperformed; narrow reflow is separate evidence.

## Elevation & Depth

The studio is flat: tonal surfaces and one-pixel structural borders, without box shadows or nested elevation cards. Card borders separate independent widgets; field borders indicate editing affordances. Settings use a subtle footer tone for the transparency note. The dialog's dim backdrop (`#172321a6`) communicates modal depth. Its native top layer supplies focus containment.

Overlay surfaces are opaque, without blur or whole-page scrims. They use a narrow operator-accent edge to help distinguish the graphic over video. Alert messages stack at most three deep. The control-room copy announcement sits above the page near the viewport bottom; the setup dialog occupies the native modal layer.

## Shapes

The brand wheel and color swatches are circles. Buttons use a 7 px radius; source panels 8 px; cards 9 px; the composition/settings panel 10 px; the dialog 14 px. Small pills and tabs use 4–6 px. Broadcast surfaces use 16 px, with progress bars fully rounded. Inner controls stay inset from outer surfaces. The preview masks only the composition canvas; source URLs and telemetry evidence remain fully available.

The wheel icon, line icons, favicon, share SVG/PNG and scene art are local assets. `src/scripts/icons.js` supplies one consistent set of `currentColor` SVG outlines at 1.7 stroke width; decorative icons have `aria-hidden`. No icon is the sole accessible name of a control.

Window ratios are derived from exact stored deltas using the current rim circumference. The log does not cache a ratio that could outlive a calibration change.

Animations are functional: the ticker eases for 1800 ms using a cubic count interpolation, commands rotate every 8000 ms, and a new recorded-round event outlines three times over 1800 ms with a six-second textual state. Reduced motion disables interpolation, command rotation and flashing. The control room's motion pause reaches every preview; live data continues. Buttons have 120 ms property-specific feedback and `scale(.96)` only when motion is allowed. There is no `transition: all` or autoplay video.

## Do's and don'ts

- Start a new studio section from `.section-heading` and the main grid/inset. Keep operator controls above or next to their output.
- Reuse semantic color and type tokens; preserve the light studio and explicitly chosen widget theme.
- Keep one visually primary action in the active workspace. Peer card copy buttons remain outlined.
- Keep measurement values tied to actual polls. Show an age and an explicit word for failures; never substitute demo telemetry for live data.
- Preserve the transparent root and `color-scheme: normal` on overlay pages. Put readable text on a theme surface.
- Use a native button, link, form field, details or dialog before adding custom interaction behavior. Preserve visible keyboard focus.
- Keep exact source values available when presenting rounded ratios. Never classify a chain-settlement lag alone as fabricated work.
- For another widget, add its metadata to `WIDGETS`, export a real `src/overlay/<name>/index.html`, reuse `widgets.js` configuration/data handling and `overlay.css` tokens, then check both broadcast canvases and themes before rebuilding.
